# WEDNELLO — конструктор свадебных приглашений

Сервис для пар (B2C): лендинг, мастер создания за 3 шага, личный кабинет с конструктором, гостями и ответами, совместное редактирование с партнёром. **Гости** открывают персональную ссылку и отвечают на анкету. Оплата пока не подключена: у всех аккаунтов один бесплатный тариф «Личный» (`shared/core.js → DEFAULT_PLANS`).

Дизайн: Cormorant Garamond + Manrope, светлая палитра слоновой кости с латунным акцентом, фотографии в `web/public/img` (исходники в `design/src`).

## Что умеет

**Конструктор приглашения**
- Живой предпросмотр в рамке телефона или компьютера; кнопка «Изменить» прямо в превью открывает нужный раздел, а выбор раздела в панели прокручивает превью к нему.
- Разделы: пара и дата (часовой пояс, город), место церемонии и банкета (ссылка на карту подставляется сама), **план дня** (перетаскивание, иконки, дублирование, упорядочивание по времени, 4 готовых сценария), фото (места под конкретный шаблон, точка фокуса, подписи кадров), дресс-код (палитра, готовые наборы), анкета (срок, автозакрытие, число гостей, питание, пожелания, свои вопросы), все тексты шаблона с подстановками `{Имена}`, `{Дата}`, `{Церемония: адрес}` и т. д., музыка, смена шаблона и тема (у Ivory).
- Автосохранение, отмена и повтор (Ctrl+Z / Ctrl+Shift+Z), просмотр «глазами гостя» с персональным обращением.
- Публикация: проверка готовности, свой адрес `/i/имя-пары`, QR-код для печатных приглашений, Telegram/WhatsApp. Гости видят опубликованную версию, черновые правки не утекают.

**Гости и ответы**
- Список гостей: вставка списка целиком (`Имя; мест; группа`), автоматическое обращение «Дорогой / Дорогая / Дорогие», группы, телефоны.
- Персональная ссылка для каждого гостя: обращение по имени на заставке, имя и число мест уже заполнены в анкете. Видно, кто открыл приглашение и сколько раз.
- Шаблон сообщения со ссылкой, отправка в мессенджеры, отметка «отправлено».
- Ответы: сколько человек придёт, кто не сможет, кого ждём, питание и аллергии, сводка по своим вопросам, пожелания. Выгрузка в CSV и копирование в Google Таблицы.

**SaaS-часть**
- Студия: брендинг (логотип, цвет, подпись в приглашениях, сайт), команда с ролями владелец/менеджер.
- Кабинет пары по ссылке без регистрации, под брендом студии. Пара правит приглашение и ведёт гостей; публикует сама, если студия разрешила, иначе отмечает «Готово», и студия видит это на дашборде.
- Тарифы с лимитами (активные приглашения, гости, команда) и возможностями (все шаблоны, музыка, кабинет пары, white-label, без отметки платформы, выгрузка). Администратор платформы редактирует тарифы в интерфейсе: цены, лимиты, возможности, порядок, рекомендуемый.
- Архив прошедших свадеб не занимает лимит.

## Шаблоны

| Папка | Название | Фото |
|---|---|---|
| `web/public/templates/cinema` | Кинопремьера | 5 кадров на экране + 4 на плёнке |
| `web/public/templates/photobooth` | Фотобудка | 3 кадра на полоске + большое фото |
| `web/public/templates/book` | Книга | 2 полароида |
| `web/public/templates/ivory` | Ivory Letter | овал и арка |

Анимации и вёрстка исходных шаблонов сохранены. Что изменено:
- Тексты, списки, фото и разделы размечены атрибутами `data-t`, `data-v`, `data-list` + `<template data-item>`, `data-slot`, `data-sec`. Их заполняет общий рантайм `templates/_runtime/runtime.js`. Без данных шаблон показывает исходный текст.
- Из `script.js` убраны встроенные CONFIG, подгрузка фото и обработчик формы: этим занимается рантайм (анкета, свои вопросы, музыка, обращение к гостю, отправка ответа).
- Ivory подключён через `ivory/vz-bridge.mjs`: модель конструктора превращается в его `config.json` и проходит его же валидацию. В `safeUrl` разрешены `data:`/`blob:` картинки для превью.
- PNG-ассеты пережаты в WebP: вес шаблонов уменьшился с ~33 МБ до ~11 МБ, приглашение у гостя открывается в разы быстрее.

Тексты и места под фото каждого шаблона описаны в `shared/templates.js`. Новый шаблон добавляется так: разметить HTML атрибутами выше, подключить `../_runtime/runtime.js` и описать шаблон в каталоге.

## Как устроено

```
shared/       общая логика: каталог шаблонов, модель данных, API-ядро, демо-данные
  core.js     все маршруты API и правила тарифов (работает и в Node, и в браузере)
  model.js    данные приглашения → модель для шаблона, подстановки, даты, готовность
web/src/      интерфейс на React 19 (сборка esbuild)
web/public/   шаблоны и рантайм
server/       Node-сервер без зависимостей: API, /i/:slug, загрузки, статика
```

Интерфейс сначала ищет сервер (`/api/health`). Если сервера нет, например на статическом хостинге, то же ядро запускается прямо в браузере поверх IndexedDB. Это демо-режим, данные живут в браузере.

## Запуск

```sh
npm install
npm run build
npm start            # http://localhost:3000, демо-вход demo@wednello.ru / demo123
```

Переменные окружения: `PORT` (3000), `DATA_DIR` (./data: база и загрузки), `DEMO=0` отключает демо-студию.

Публичная страница гостя `/i/<адрес>?g=<токен>` отдаётся сервером сразу с данными (без мигания), с OG-тегами для превью ссылки в мессенджерах. Ответы принимаются на `POST /api/public/rsvp/<адрес>`, частота ограничена.

## Перед запуском в продакшен

- **База**: `server/index.js` хранит всё в `data/db.json`. Для реальной нагрузки замените `store` на Postgres (таблицы повторяют коллекции из `emptyDb()` в `shared/core.js`).
- **Файлы**: загрузки лежат в `data/uploads`. Подключите S3-совместимое хранилище и CDN.
- **Оплата**: смена тарифа сейчас мгновенная. Подключите ЮKassa / CloudPayments в `POST /workspace/plan`.
- **Почта**: приглашение участника команды выдаёт временный пароль на экране. Добавьте письма и сброс пароля.
- **Домены**: свой домен студии для приглашений (white-label) — через прокси и поле в настройках студии.
- **Шрифты** шаблонов грузятся с Google Fonts. Для аудитории в РФ лучше раздавать их со своего сервера.
